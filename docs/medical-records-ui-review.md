# ข้อเสนอรีวิว UI: หน้าผลตรวจและรายการยา

วันที่รีวิว: 22 กันยายน 2026  
สถานะ: ข้อเสนอเพื่อเลือก ยังไม่แก้ไขโค้ด

## เป้าหมาย

ทำให้หน้าผลตรวจและรายการยาอ่านง่ายขึ้น ลดความสับสนระหว่างข้อมูลของแพทย์กับข้อมูลของผู้ป่วย และทำให้ข้อความสื่อความหมายตรงกับการใช้งานจริงในคลินิก

ขอบเขตที่รีวิว:

- หน้าผลตรวจของแพทย์
- หน้าประวัติการรักษาของผู้ป่วย
- ฟอร์มบันทึกผลตรวจแบบหลายขั้นตอน
- ฟอร์มรายการยาและการแสดงรายการยาที่สั่ง

## หลักการที่ควรรักษาไว้

- เก็บข้อมูลไว้ในฟอร์มจนกดยืนยันครั้งสุดท้าย ไม่เพิ่มระบบบันทึกฉบับร่าง
- เมื่อกด `เริ่มตรวจ` ให้เปิดฟอร์มผลตรวจใน flow นัดหมายทันที
- แยกสถานะ `จบตรวจแล้ว` และ `รอจบตรวจ` ให้เห็นชัด
- แพทย์สามารถข้ามขั้นตอนรายการยาได้เมื่อไม่มีการสั่งยา
- ระบุชัดว่า “รายการยาที่สั่ง” ไม่ใช่ “สถานะการจ่ายยา”

## สรุปตัวเลือก

เลือกเป็นชุดได้ด้วยการติ๊กหัวข้อที่ต้องการส่งต่อให้เจ้าของฟีเจอร์

- [ ] **A — จัดลำดับหัวข้อและแก้ H1 ซ้ำ**: ควรทำก่อน เพราะกระทบความเข้าใจทั้งหน้า
- [ ] **B — ปรับข้อความภาษาไทย**: ลดคำแปลตรงตัวและทำให้คำสั่งชัดขึ้น
- [ ] **C — ปรับ layout ฟอร์มรายการยา**: แก้ปัญหาช่องข้อมูลล้นและการจัดกลุ่มที่อ่านยาก
- [ ] **D — ปรับชื่อขั้นตอนใน Stepper**: ลดคำอังกฤษเชิงระบบ ให้เหมาะกับผู้ใช้คลินิก
- [ ] **E — ปรับรายการประวัติผลตรวจ**: ทำให้ค้นหา อ่านวันที่ และแยกกรณีไม่มีข้อมูลได้ชัด

ข้อเสนอแนะ: อย่างน้อยควรเลือก **A + C + E** เพราะเป็นปัญหาโครงสร้างและการอ่านข้อมูลโดยตรง ส่วน **B + D** เป็นชุดปรับความชัดเจนของภาษาและสามารถทำพร้อมกันได้

## A — จัดลำดับหัวข้อและแก้ H1 ซ้ำ

### ปัญหาที่พบ

หน้าของแพทย์แสดงหัวข้อ `ผลตรวจและรายการยา` ซ้ำเป็น H1 ทั้งจาก Shell และ Intro ทำให้ลำดับความสำคัญของเนื้อหาไม่ชัด และโปรแกรมอ่านหน้าจออ่านโครงสร้างซ้ำ

### โครงสร้างที่เสนอ

#### แพทย์

- H1: `ผลตรวจและรายการยา`
- H2: `บันทึกผลตรวจ`
- H2: `ประวัติผลตรวจผู้ป่วย`

#### ผู้ป่วย

- H1: `ประวัติการรักษา`
- H2: `ผลตรวจและรายการยาของฉัน`

ควรมี H1 เพียงหนึ่งรายการต่อหน้า และให้ส่วนฟอร์มกับส่วนประวัติใช้ H2 แยกกัน

## B — ปรับข้อความภาษาไทย

| ข้อความปัจจุบัน | ข้อความที่เสนอ | เหตุผล |
|---|---|---|
| นัดหมาย ผลตรวจ และรายการยาของบัญชีนี้เท่านั้น | ดูนัดหมาย ผลตรวจ และรายการยาของคุณ | เป็นภาษาที่ผู้ป่วยเข้าใจง่ายกว่า |
| บันทึกผลตรวจและรายการยาให้ครบถ้วนก่อนส่งต่อผู้ป่วย | บันทึกผลตรวจ คำแนะนำ และรายการยาก่อนยืนยันผลตรวจ | บอกสิ่งที่ต้องทำจริง และไม่ทำให้เข้าใจว่าเป็นการส่งต่อข้อมูล |
| ผลตรวจ / แพทย์ | บันทึกผลตรวจ | สื่อว่าหน้านี้เป็นพื้นที่ทำงานของแพทย์ |
| ผลตรวจ / ผู้ป่วย | ประวัติการรักษาของฉัน | สื่อความเป็นเจ้าของข้อมูลชัดขึ้น |
| แสดงเฉพาะข้อมูลที่เปิดดูได้ | แสดงเฉพาะผลตรวจที่คุณมีสิทธิ์ดู | อธิบายขอบเขตข้อมูลให้ผู้ใช้เข้าใจ |
| ไม่มียาให้ข้ามขั้นตอนนี้ได้ | หากไม่มีรายการยา ให้กด “ถัดไป” ได้ | เปลี่ยนจากคำบอกกว้าง ๆ เป็นคำแนะนำที่ทำตามได้ |
| จบตรวจพร้อมบันทึกผล | จบการตรวจหลังบันทึก | ลดความกำกวมว่าเป็น checkbox หรือปุ่มจบตรวจ |
| รายการสั่งยาไม่ใช่หลักฐานการจ่ายยา ติดต่อจุดจ่ายยาตามขั้นตอนของคลินิก | รายการนี้เป็นคำสั่งยา ไม่ใช่สถานะการจ่ายยา หากต้องการรับยา โปรดติดต่อจุดจ่ายยา | อ่านเป็นประโยคธรรมชาติ และแยก “คำสั่งยา” ออกจาก “การจ่ายยา” |

### ข้อความแจ้งเตือนก่อนยืนยัน

ข้อความปัจจุบัน:

> ตรวจทานข้อมูลก่อนยืนยัน เพราะผลตรวจและใบสั่งยาแก้ไขไม่ได้หลังบันทึก

ข้อความที่เสนอ:

> โปรดตรวจสอบข้อมูลให้เรียบร้อยก่อนยืนยัน เนื่องจากหลังบันทึกแล้วจะแก้ไขไม่ได้

## C — ปรับ layout ฟอร์มรายการยา

### ปัญหาที่พบ

ฟอร์มใช้ grid 4 คอลัมน์ แต่มีข้อมูล 5 ช่อง ทำให้ช่องสุดท้ายตกไปอยู่ตำแหน่งที่ไม่สัมพันธ์กับช่องก่อนหน้า โดยเฉพาะหน้าจอขนาดกลาง นอกจากนี้ปุ่มลบขนาด 32×32 px เล็กกว่าขนาดเป้าหมายที่เหมาะกับการแตะ

### Layout ที่เสนอ

```text
ยา                                                   [เลือกยา]

ขนาดยาต่อครั้ง          จำนวนที่สั่ง          ระยะเวลา

วิธีใช้ / ความถี่                             การใช้ยากับอาหาร
```

### ข้อความ field ที่เสนอ

| ข้อความปัจจุบัน | ข้อความที่เสนอ |
|---|---|
| ขนาดยาต่อครั้ง (ระบุหน่วย) | ขนาดยาต่อครั้ง |
| ช่วงเวลาและความถี่ในการใช้ยา | วิธีใช้ / ความถี่ |
| จำนวนที่สั่ง | จำนวนที่สั่ง (หน่วยยา) |

### รายละเอียดการจัดวาง

- วางปุ่ม `เพิ่มรายการยา` ข้างหัวข้อ `รายการยาที่สั่ง` เพื่อให้ผู้ใช้พบ action หลักเร็วขึ้น
- แยกช่องเลือกยาไว้เต็มแถว เพราะเป็นข้อมูลหลักของรายการ
- จัดจำนวนยาและระยะเวลาให้อยู่กลุ่มเดียวกับขนาดยา
- ให้ช่องวิธีใช้กว้างกว่าช่องสั้น และวางการใช้ยากับอาหารไว้ในกลุ่มคำแนะนำ
- ขยายปุ่มลบให้มีพื้นที่กดอย่างน้อย 44×44 px พร้อม `aria-label` ที่ระบุหมายเลขรายการ

## D — ปรับชื่อขั้นตอนใน Stepper

### ปัญหาที่พบ

คำกำกับขั้นตอน `TRIAGE`, `CLINICAL SUMMARY`, `PRESCRIPTION`, `REVIEW` เป็นคำอังกฤษเชิงระบบและมีน้ำหนักด้านการตลาดมากกว่าคำอธิบายงานจริง อาจทำให้ผู้ใช้ที่ไม่คุ้นศัพท์ทางระบบสับสน

### ชื่อและคำอธิบายที่เสนอ

| ขั้นตอน | ชื่อปัจจุบัน | ชื่อที่เสนอ | คำอธิบายที่เสนอ |
|---:|---|---|---|
| 1 | การตรวจร่างกายเบื้องต้น | สัญญาณชีพ | บันทึกข้อมูลจากการคัดกรอง |
| 2 | สรุปผลตรวจ | ผลวินิจฉัย | ระบุผลวินิจฉัยและคำแนะนำ |
| 3 | รายการยา | รายการยา | เพิ่มยาที่สั่ง |
| 4 | ตรวจทานและยืนยัน | ตรวจทาน | ตรวจสอบข้อมูลก่อนยืนยัน |

เนื้อหาหลักของแต่ละขั้นตอนยังคงเดิม เพียงปรับคำบน Stepper ให้สั้นและสแกนได้เร็วขึ้น

## E — ปรับรายการประวัติผลตรวจ

### 1. เปลี่ยนเป็นรายการเรียงแนวตั้ง

การ์ดผลตรวจมีข้อมูลค่อนข้างยาว เมื่อแสดง 2 คอลัมน์บนจอใหญ่ ผู้ใช้ต้องสลับสายตาเพื่ออ่านข้อมูลทางคลินิก แนะนำให้ใช้รายการ 1 คอลัมน์เรียงตามเวลา และคง grid ไว้เฉพาะข้อมูลสัญญาณชีพภายในการ์ด

### 2. ระบุความหมายของวันที่

ปัจจุบันแสดงวันที่จาก `record.created_at` แต่ไม่มี label ชัดเจน ควรเขียนว่า:

- `วันที่บันทึกผล` หากใช้เวลาที่สร้าง medical record
- `วันที่ตรวจ` หากมีวันที่ตรวจจาก appointment และนำมาแสดงแทน

ไม่ควรใช้เพียงไอคอนปฏิทินกับตัวเลขวันที่ เพราะผู้ใช้อาจไม่รู้ว่าเป็นวันที่ตรวจหรือวันที่บันทึก

### 3. ปรับข้อความ filter

| ข้อความปัจจุบัน | ข้อความที่เสนอ |
|---|---|
| เฉพาะนัดที่เลือก | แสดงเฉพาะผลตรวจจากนัดนี้ |
| ค้นหาชื่อ แพทย์ หรือผลวินิจฉัย | ค้นหาชื่อผู้ป่วย แพทย์ หรือผลวินิจฉัย |

### 4. แยก empty state ตามสาเหตุ

ไม่ควรใช้ข้อความเดียวกับทุกกรณี แนะนำให้แยกเป็น:

- ไม่มีข้อมูลทั้งหมด: `ยังไม่มีผลตรวจ`
- ค้นหาแล้วไม่พบ: `ไม่พบผลตรวจที่ตรงกับการค้นหา`
- เลือกนัดแล้วไม่พบ: `ไม่พบผลตรวจจากนัดนี้`

ข้อความรองที่ใช้ร่วมกันได้: `เมื่อมีผลตรวจ รายการจะแสดงที่นี่`

### 5. ปรับชื่อหัวข้อผู้ป่วยของแพทย์

จาก:

> ผลตรวจและประวัติผู้ป่วยที่รับผิดชอบ

เป็น:

> ผลตรวจของผู้ป่วยในความดูแล

สั้นลง อ่านง่าย และยังรักษาความหมายเรื่องขอบเขตสิทธิ์ไว้

## สิ่งที่ถือว่าใช้ได้แล้ว

- การแบ่งข้อมูลเป็นการตรวจร่างกายเบื้องต้น ผลวินิจฉัย คำแนะนำ และรายการยา
- การใช้ status chip `จบตรวจแล้ว` และ `รอจบตรวจ`
- การมีหน้าตรวจทานก่อนบันทึกครั้งเดียว
- การแจ้งว่าไม่มีรายการยาได้ และไม่บังคับให้เพิ่มยา
- การแยกข้อมูลคำสั่งยาออกจากสถานะการจ่ายยา แม้ควรปรับถ้อยคำให้อ่านง่ายขึ้น

## ข้อมูลที่ต้องให้เจ้าของฟีเจอร์ตัดสินใจ

1. วันที่บนการ์ดต้องการสื่อ `วันที่ตรวจ` หรือ `วันที่บันทึกผล`
2. ต้องการให้รายการผลตรวจเรียงเก่าขึ้นก่อนหรือใหม่ขึ้นก่อน
3. ต้องการใช้ชื่อ `ผลวินิจฉัย` หรือคงชื่อ `สรุปผลตรวจ`
4. เลือกชุดการปรับปรุงข้อใดบ้างจาก A–E

## ขอบเขตการตรวจครั้งนี้
