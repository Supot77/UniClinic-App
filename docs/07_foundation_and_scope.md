# 07. ขอบเขตและสถานะโครงการ

ปรับปรุง 5 กันยายน 2569 (2026-09-05) — ข้อกำหนดสำหรับพัฒนา ยังไม่ใช่หลักฐานว่าโค้ดหรือฐานข้อมูลทำครบแล้ว

## ขอบเขตที่ต้องคง

สมาชิก/รีเซ็ตรหัสผ่าน/โปรไฟล์/ค้นหาผู้ป่วย/Admin จัดบัญชี, แผนก/แพทย์/ปฏิทิน, นัด/คิว/ผลตรวจ/ใบสั่ง, คลัง/ประวัติยา, เตือนกินยา/ประวัติมื้อ, กล่องข้อความ/Broadcast และ Dashboard ตามบทบาท ดู [02](02_user_stories.md)

## สิ่งที่เปลี่ยนจากฐานก่อนประชุม

| ฐานเก่า | ข้อสรุปล่าสุด |
| --- | --- |
| จ่ายครบใบและยังไม่รองรับแบ่งจ่าย | แบ่งจ่ายโดยเภสัชกรบันทึกเหตุผล มีค้างและกันยา |
| ผู้ป่วยสร้าง/แก้เตือนเอง | Staff สร้างจากยารับจริง ผู้ป่วยยืนยันเวลาแล้วล็อก |
| ตรวจทุก 15 นาทีแล้วส่งสองช่องทางพร้อมกัน | อีเมลก่อน 10 นาที ในเว็บถึงเวลา; worker ต้องออกแบบใหม่ |
| ยังไม่กำหนด missed/ย้อนหลัง | 1 ชั่วโมง; บันทึกถึงมื้อถัดไป +30 นาที; มื้อสุดท้าย +3 ชั่วโมงเตือนซ้ำและปิด +30 นาที |
| Admin อ่าน/จัดการทุกส่วน | บัญชี สิทธิ์ สถานะระบบและสถิติไม่เปิดข้อมูลผู้ป่วย |
| Staff ส่ง Broadcast | เฉพาะ Admin |
| เลื่อนนัดเป็นข้อเสนอเพิ่ม | อยู่ในขอบเขต: กันรอบใหม่ รอตอบ 24 ชั่วโมง แล้วตอบรับอัตโนมัติ |
| แผน 1–18 กันยายนแบบเดิม | ล็อกแบบ 5–7 พัฒนา 8–11 เชื่อม 12–14 หยุดเพิ่ม 15 ซ้อม 16–17 ส่ง 18 |

ใช้ 5 บทบาทหนึ่งบทบาทต่อบัญชี ไม่ใช้ student เป็น role; เวลา Asia/Bangkok และข้อมูลเดโม 4 แผนก 17 บัญชีตาม [Catalog](superpowers/specs/2026-09-04-clinic-demo-data-design.md)

## สถานะ implementation

ทีมรับรอง ER แบบแยกตารางแล้ว migration 03 และ types รองรับ persisted contract ใหม่แบบ additive แต่ runtime ยังใช้ mock และยังไม่ได้รัน migration/RLS/RPC กับฐานจริง

ไม่เพิ่ม walk-in, ลากวาง, กราฟขั้นสูง, Web Push, การจ่ายเงิน, หลายสาขาหรือเชื่อมโรงพยาบาลเป็นข้อบังคับ การคืนยาที่จ่ายแล้วและเรื่องที่ยังไม่ตอบดู [10](10_team_decisions.md)
