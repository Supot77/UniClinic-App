# 01. ภาพรวมโครงการฉบับย่อ

ปรับปรุง 6 กันยายน 2569 (2026-09-06)

> สถานะ: ข้อเสนอสำหรับลดขนาดระบบ ยังไม่อนุมัติให้พัฒนาและไม่เปลี่ยนระบบปัจจุบัน

## เป้าหมาย

สร้างระบบคลินิกมหาวิทยาลัยขนาดเล็กที่สาธิตเส้นทางตั้งแต่จองนัดจนถึงเตือนกินยาได้ โดยลดกฎอัตโนมัติ ธุรกรรมซับซ้อน และจำนวนข้อมูลให้เหลือระดับที่ทีมพัฒนาและทดสอบได้ทัน

ระบบเน้น 3 เรื่อง:

1. ผู้ใช้เข้าใจ flow ได้ในครั้งเดียว
2. แต่ละฟีเจอร์มี CRUD และ validation ขั้นพื้นฐาน
3. ข้อมูลจริงทั้งหมดเก็บใน Supabase ผ่าน Entity จำนวนน้อย

## บทบาทผู้ใช้

| บทบาท | หน้าที่หลัก |
| --- | --- |
| Patient | สมัคร เข้าสู่ระบบ จองนัด ดูผลตรวจ ตั้งเตือน และบันทึกว่ากินยาแล้ว |
| Doctor | ดูนัดของตน บันทึกผลตรวจ และสั่งยา |
| Staff | จัดตาราง ยืนยันนัด จัดรายการยา และจ่ายยา |

Patient สมัครผ่าน Supabase Auth ส่วนบัญชี Doctor/Staff ให้ผู้ดูแลโครงการสร้างและกำหนด role ผ่าน Supabase Dashboard ไม่มีหน้าจอจัดการบัญชีในแอปฉบับย่อ

Staff รวมงานเดิมของ Staff และ Pharmacist เพื่อลดหน้าจอและกฎสิทธิ์ ส่วนงาน Admin ในแอปถูกตัดออก

## 6 ฟีเจอร์พื้นฐาน

| ลำดับ | ฟีเจอร์ | ผลลัพธ์หลัก |
| --- | --- | --- |
| 1 | สมัครและเข้าสู่ระบบ | ผู้ใช้เข้าระบบและเห็นเมนูตาม 3 บทบาท |
| 2 | จัดการตารางตรวจ | Staff สร้าง เปิด และปิดรอบตรวจของ Doctor |
| 3 | จองและจัดการนัด | Patient จอง; Staff ยืนยันหรือยกเลิก |
| 4 | บันทึกผลตรวจ | Doctor บันทึก diagnosis, treatment และรายการยา |
| 5 | จ่ายยาและตัดสต๊อก | Staff จ่ายยาครบครั้งเดียวและลด stock |
| 6 | เตือนกินยาในเว็บ | Patient ตั้งเวลาจากยาที่จ่ายแล้วและกดว่ากินแล้ว |

## เส้นทางหลัก

1. Patient สมัครด้วยอีเมล `mail.wu.ac.th` ยืนยันอีเมลผ่าน Supabase Auth และเข้าสู่ระบบ
2. Staff สร้างรอบตรวจของ Doctor
3. Patient เลือกรอบและสร้างนัดสถานะ `pending`
4. Staff เปลี่ยนนัดเป็น `confirmed`
5. Doctor บันทึกผลตรวจและสั่งยา แล้วปิดการตรวจ
6. Staff จ่ายยาครบ หาก stock พอ ระบบลด stock และเปลี่ยนรายการเป็น `dispensed`
7. Patient สร้างเวลาเตือนจากรายการที่จ่ายแล้ว และกด `taken` เมื่อกินยา

## ตัวชี้วัดความสำเร็จของข้อเสนอ

- มีเพียง 7 Entity และ 3 บทบาท
- Flow หลักจบได้บน Supabase โดยไม่พึ่ง worker หรือ email
- ทุกคำสั่งสำคัญมี validation, RLS และกรณี error ที่เข้าใจได้
- Runtime ไม่มี localStorage/mock data; automated tests ใช้ mock/fake และไม่พึ่ง network
- การจ่ายยาทั้งชุดใช้ PostgreSQL RPC เพื่อให้ตัด stock แบบ transaction
- UI ที่เสนอรองรับ Chrome ขนาด 360px และ 1280px และใช้งานหลักด้วย keyboard
