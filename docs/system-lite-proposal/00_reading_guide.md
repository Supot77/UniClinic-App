## หลักการตีความ

- คำว่า “ต้อง” หมายถึงพฤติกรรมที่เสนอสำหรับระบบฉบับย่อ ไม่ได้อนุญาตให้เริ่มพัฒนา
- Runtime เก็บข้อมูลทั้งหมดใน Supabase Auth และ PostgreSQL ไม่มี localStorage หรือ mock data เป็นแหล่งข้อมูลจริง
- ข้อเสนอครอบคลุม schema, migration, RLS และ RPC สำหรับจ่ายยา แต่ยังไม่มีการสร้างหรือรันสิ่งเหล่านี้
- Mock ใช้เฉพาะ automated tests ตาม contract เดียวกับ Supabase repository
- ไม่มี email, worker หรือ cron; secret/legacy `service_role` key ห้ามอยู่ใน browser และข้อเสนอนี้ไม่ต้องใช้ในแอป
- หากข้อเสนอนี้ขัดกับเอกสารหลัก ให้ถือว่าเอกสารหลักยังมีผลจนกว่าทีมจะอนุมัติการเปลี่ยนขอบเขตอย่างเป็นทางการ
- หลังอนุมัติจริง ต้องประเมินโค้ดปัจจุบันใหม่ก่อนวางแผนลบหรือแก้ส่วนใด

## ภาพรวมฉบับย่อ

```text
Patient จองรอบตรวจ
  → Staff ยืนยันนัด
  → Doctor ตรวจและสั่งยา
  → Staff จ่ายยาและตัดสต๊อก
  → Patient ตั้งเวลาเตือนและบันทึกว่ากินแล้ว
```
